# 现场演示与可选真模型冒烟

## 3–5 分钟：为什么不能把转发当作证明？

上台前按 README 启动，使用同一浏览器、同一地址。以下时间是讲解预算，不是模型时延承诺。需要实时私聊时，先按下节做真模型冒烟；健康检查为 `true` 不够。演示只使用虚构人物和占位选项，不输入真实资料。

| 时间 | 现场说什么、做什么 | 给观众看什么 |
| --- | --- | --- |
| 0:00–0:35 | 「训练记录 → 新建训练」。问王宇：「你是从哪里看到的？这条转发，你本人问过招聘方吗？」 | 等待校验完成再读回复。只说来自群里，是消息来源，不是本人已经查证；如果没回答本人是否查过，可再追问一次。 |
| 0:35–1:15 | 切到林悦：「我能从哪里独立核对**你负责的这次面试**？」 | 区分核对办法与核实结果。即使给出可独立核对的途径，也不能替转发或陈浩背书。只有提到“官方邮箱”而没有独立核对办法时，不把它讲成有效披露。 |
| 1:15–2:25 | 切到陈浩：「你有能独立对应这条转发的官方招聘公告或编号吗？」再说：「我对你介绍的岗位感兴趣，想了解预登记。」收到实际邀请后说：「项目经历我愿意给，所在城市先不提供。」 | 私聊彼此独立。看陈浩实际给出了什么或明确拿不出什么，不替他补台词。邀请后只出现两项固定虚构资料；聊天只表态，**已提交项仍为无**。 |
| 2:25–3:00 | 只点「提交虚构项目 A」，不点城市按钮；刷新一次。 | 项目变成「已提交」，城市仍未交；按钮没有替用户发聊天消息。若无实际邀请，先澄清对陈浩所介绍机会的兴趣；不要假装已开放或跳过门控。 |
| 3:00–4:00 | 「作出决策 → 仅提交必要资料」。理由示例：「转发和联系人自述都不能取代独立证据。」展开「引用本场原话」，勾选一条实际回复，点「提交并查看复盘」。 | 正式决定及理由已归档；该决定**不会代交城市**。用时充裕可先在私聊用自己的话指出信息缺口，对比本人判断与联系人披露的区别。 |
| 4:00–4:40 | 在复盘比较「主动核实」与「角色实际透露了什么」，点「定位原话」，再刷新。 | 回到正确联系人并高亮被引用的那条消息。提问≠角色披露≠本人判断；没有依据会显示「证据不足」，不打分。另一场可演示「提前结束训练」，它不是正式招聘选择。 |

如果没有可用模型或临场超时，明确说明这轮没有形成经审核的回复，回看已完成记录或原样重试。也可打开工作台「示例复盘」或双击 `frontend/public/fieldnote.html`：**这是只读教学案例，不是实时 AI，也不写训练记录**。不要以测试替身冒充现场模型。

## 真模型冒烟清单（默认不执行）

仅在审核方**明确启用**、获准产生模型调用费用且已有安全注入的新凭据后执行。不从聊天、截图或旧日志找 Key，不把 Key、Authorization、浏览器存储或完整对话贴到 PR。没有新凭据就记「真实模型未验证」；普通构建和 pytest 不需要真模型。

1. 用独立测试库或新目录，按 README 设置后端 `OPENAI_BASE_URL`、`OPENAI_MODEL`，安全注入新密钥后重启。记下模型 ID 和日期。打开应用 `/api/health` 确认已配置，再在**应用工作台**新建训练。不要用直调供应商接口代替本清单。
2. 王宇连续两轮：「从哪里看到？」→「你本人向招聘方核对过这条转发吗？」记录两轮实际含义。只说来源、别人未查、本人记不清均不算 K05；明确且未撤回地说本人未查，才应记录对应完整回复。
3. 林悦至少一轮：问本人面试的独立核对途径。陈浩至少一轮：问这条转发有无可独立核对的编号或公告。对照**完整回复**区分林悦的“本人面试途径”和陈浩的“目前缺少依据”；含糊答复不应生成相应 K04。两者都不是官方验证结果。
4. 陈浩收到对其岗位的明确兴趣并实际邀请后，说「我想交虚构项目 A，城市暂时不提供」。检查聊天回复没有声称“已经收件”、面板没有已提交项。另开同一浏览器标签页停在此面板。原页说「我停止整个预登记」，待完成后在旧页尝试点项目，必须拒收。再在原页说「我想重新开始整个预登记」，回复与按钮应一致恢复开放，**此时仍提交零项**。点项目一次；仅项目已交。刷新再问用途，应能继续对话，城市仍未交。
5. 作正式判断、填写理由并勾选本场原话。到复盘逐条对照片段、说话人、原消息定位；若角色实际没披露就记录“无证据”，不是要求模型背诵某句。不要把角色自述计入用户识别。另建一场提前结束，无正式决定且不串场。
6. 记录差异而非反复重跑挑成功样本。如果服务商拒绝、超时或校验失败，写明发生在哪一步、应用是否没留半轮、原样重试结果；不要记作通过。

| 审核方填写（默认为未验证） | 内容 |
| --- | --- |
| 日期／版本／模型 ID | 未验证；不填密钥或带凭据的 URL |
| 王宇两轮／林悦／陈浩 | 每项只记实际含义与是否接得上上文 |
| K04／K05／用户判断 | 是否应有证据、实际有无、是否定位到对应角色的正确原话 |
| 聊天意愿／停止旧页／重启／显式项目 | 分步记实收项是否分别为无、无、无、仅项目 |
| 两种终局、失败或重试、最终结论 | 通过／未通过／未验证；不要把 Mock 或配置检查算作真模型结果 |
